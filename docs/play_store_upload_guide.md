# 🚀 처음 해보는 사람도 100% 성공하는 구글 플레이 스토어 파헤치기 (A-Z 가이드)

이 문서는 안드로이드 앱(AAB)을 구글 플레이 콘솔에 처음 업로드하고, 내부 테스터들에게 배포하여 스마트폰에 직접 설치하기까지의 모든 과정을 누구나 따라 할 수 있도록 가장 직관적이고 상세하게 설명합니다.

---

## 📋 핵심 요약 (5단계 프로세스)

| 단계 | 작업명 | 목적 | 소요 시간 |
| :--- | :--- | :--- | :--- |
| **Step 1** | **플러터에서 AAB 파일 생성** | 플레이 스토어 전용 압축 파일(App Bundle) 생성 | 1분 |
| **Step 2** | **구글 플레이 콘솔 앱 생성** | 내 앱이 들어갈 빈 방(프로젝트) 만들기 | 3분 |
| **Step 3** | **필수 정책(개인정보) 설정** | 깐깐한 구글 정책 통과를 위한 필수 입력 | 2분 |
| **Step 4** | **내부 테스트에 파일 업로드** | 만든 AAB 파일을 구글 서버에 업로드 | 3분 |
| **Step 5** | **테스터 초대 및 다운로드** | 스마트폰의 '플레이 스토어'를 통해 설치 | 5분 |

---

## 📖 상세 진행 가이드 (Step-by-Step)

### 💻 Step 1: 안드로이드 스튜디오(플러터)에서 AAB 파일 뽑아내기
구글은 보안 강화를 위해 기존의 구형 `APK` 파일 대신 최신 `AAB(App Bundle)` 규격만을 새 버전으로 허용합니다.

1. **터미널 열기**: 안드로이드 스튜디오 (또는 VS Code) 하단의 Terminal(터미널) 탭을 엽니다.
2. **명령어 입력**: 아래 명령어를 그대로 복사해서 붙여넣고 엔터를 칩니다.
   ```bash
   flutter build appbundle --release
   ```
3. **완료 대기**: 잠시 기다리면 초록색 체크마크(`✓ Built...`)와 함께 파일이 완성됩니다.
4. **파일 경로 확인**: 만들어진 파일의 위치는 프로젝트 폴더 내 `build/app/outputs/bundle/release/app-release.aab` 입니다. (나중에 드래그해야 하니 폴더를 열어두세요.)

---

### 🌐 Step 2: 구글 플레이 콘솔(Google Play Console) 앱 생성하기
건물을 짓기 전에 땅을 먼저 사야 하듯, 앱 파일을 올리기 전에 구글 콘솔에 내 앱의 빈방을 만들어야 합니다.

1. 인터넷 창을 열고 [구글 플레이 콘솔](https://play.google.com/console) 에 접속하여 로그인합니다.
2. 화면 우측 상단이나 중앙의 **[앱 만들기]** 라는 파란색 버튼을 클릭합니다.
3. 앱 정보를 입력합니다.
   - **앱 이름**: `비즈후` (출시 전 언제든 변경 가능)
   - **기본 언어**: `한국어(대한민국)`
   - **앱 또는 게임**: `앱`
   - **무료 또는 유료**: `무료`
4. 화면 맨 아래의 필수 체크박스(개발자 프로그램 정책, 미국 수출법)에 모두 체크합니다.
5. 우측 하단의 **[앱 만들기]**를 클릭하면 내 앱의 메인 대시보드로 이동합니다.

---

### 🛡️ Step 3: 필수 정책(개인정보처리방침) 설정하기
앱이 전화번호부, 통화 기록 등 민감한 권한을 사용하려면 구글에게 "우리는 고객 정보를 이렇게 다루고 있다"는 법적 고지(URL)를 제출해야 합니다.

1. 화면 가장 왼쪽 상단의 **[대시보드]** 메뉴를 클릭합니다.
2. 메인 화면 중앙에 있는 **[앱 설정 완료(Set up your app)]** 라는 큰 제목을 찾아 클릭하거나 펼칩니다.
3. 펼쳐진 목록 첫 번째에 있는 **[개인정보처리방침 설정]** 항목을 클릭합니다.
4. 빈칸(URL 입력란)이 나오면 아래 주소 중 하나를 입력합니다. (실제 서비스 시에는 진짜 회사 홈페이지의 약관 페이지를 넣어야 합니다.)
   - 예시 (임시 통과용): `https://blog.naver.com/bizwho_privacy`
   - 주의: `https://www.google.com` 같은 유명 포털 주소는 구글의 봇(Bot)이 잡아내서 오류를 냅니다.
5. 우측 하단의 **[저장]** 버튼을 누릅니다.

---

### 🚀 Step 4: 내부 테스트(Internal Testing)에 파일 업로드
대중에게 공개하기 전, 지정된 사람(테스터)들만 스토어에서 앱을 설치해 볼 수 있는 '비밀 공간'에 앱을 올립니다.

1. 화면 가장 왼쪽 메뉴에서 마우스 휠을 굴려 **[테스트]** 메뉴 그룹을 찾은 뒤, **[내부 테스트]** 를 클릭합니다.
2. 우측 상단의 **[새 버전 만들기]** 파란색 버튼을 누릅니다.
   - (만약 "앱 파트너 서명 동의" 팝업이 뜨면 '계속'을 누릅니다.)
3. 중앙의 큼지막한 점선 박스(**App Bundle 및 APK**) 영역에 아까 `Step 1`에서 만든 `app-release.aab` 파일을 마우스로 끌어다 놓습니다. (드래그 앤 드롭)
   - 파란색 바가 차오르며 업로드가 진행됩니다.
4. 이 단계에서 `대상 SDK를 35로 올려야 합니다`라는 오류가 난다면, [부록](#target-sdk)을 참고하세요.
5. 파일 업로드가 완료되면 그 아래쪽 **[출시 노트]** 입력 칸에 이번 업데이트 내용을 간단히 적습니다. (예: `기본 오버레이 기능 테스트 버전`)
6. 우측 하단 **[다음]** 을 누른 뒤, 나오는 화면에서 오류(빨간색 느낌표)가 없다면 **[저장]** 후 **[출시(또는 배포)]** 를 클릭합니다. (노란색 경고 표시는 무시해도 됩니다.)

---

### 👥 Step 5: 테스터 추가 및 스토어에서 다운로드 받기
앱을 올렸으니, 이제 "누가 이 앱을 다운받을 수 있는지" 권한을 주고 그들에게 주소를 알려줍니다.

1. 다시 왼쪽 메뉴의 **[내부 테스트]** 로 돌아가서, 상단 탭 중 **[테스터]** 탭을 클릭합니다.
2. 처음이라면 **[이메일 목록 만들기]** 링크나 아이콘을 눌러 목록을 만듭니다.
3. 테스트를 진행할 분들의 **스마트폰에 로그인되어 있는 구글 계정(Gmail)**을 쭉 입력하고 엔터를 쳐서 등록합니다. 꼭 개발자 본인 이메일도 넣으세요.
4. 목록 작성이 끝났다면 우측의 화살표(또는 저장)를 눌러서 닫습니다.
5. 이제 해당 이메일 목록 박스 왼쪽에 **[체크(v)]** 표시를 해서 테스터를 활성화시킨 후 우측 하단 **[변경사항 저장]**을 누릅니다.
6. 화면 스크롤을 살짝 아래로 내리면, **[참여 링크 복사 (테스터 참여 URL)]** 라는 버튼이 보입니다. 클릭해서 링크를 복사합니다.
7. 이 링크를 **카카오톡** 등으로 내 폰(또는 테스터의 폰)으로 보냅니다.
8. **스마트폰에서 카톡으로 온 링크를 누릅니다.**
9. 브라우저가 열리면 화면 아래쪽 **[초대 수락 (Accept Invitation)]** 을 클릭합니다.
10. 수락 완료 메시지 바로 밑에 있는 파란색 글씨 **[구글 플레이에서 다운로드 (Download it on Google Play)]** 를 클릭합니다.
11. 폰에 설치된 **Google Play 스토어 앱이 자동으로 스르륵 열리며**, [비즈후(내부 테스트)] 앱 설치 화면이 뜹니다. **[설치]**를 누르면 끝입니다! 🎉

> [!NOTE]
> ### 💡 부록: 자주 겪는 업로드 오류 대처법
>
> 🔴 **오류 1: 대상 SDK를 35로 올려야 합니다.**
> 안드로이드 정책은 매년 강화됩니다. 새로운 앱을 올릴 때 API 수준 오류가 발생했다면 다음과 같이 조치하세요.
> 1. 안드로이드 스튜디오의 왼쪽 파일창에서 `android/app/build.gradle.kts` 파일을 찾아 엽니다.
> 2. 코드 중간에 있는 `targetSdk = 34` 라고 적힌 숫자를 **`35`** 로 변경합니다.
>
> 🔴 **오류 2: N 버전 코드는 이미 사용되었습니다. 다른 버전 코드를 사용해 보세요.**
> 구글 플레이는 이전에 한 번이라도 업로드에 실패했거나 성공했던 버전의 '고유 식별 번호(versionCode)'를 똑같이 재사용하는 것을 엄격히 금지합니다.
> 1. 안드로이드 스튜디오의 왼쪽 파일창에서 `android/app/build.gradle.kts` 파일을 찾아 엽니다.
> 2. 코드 중간에 있는 `versionCode = N` (오류가 난 숫자) 부분을 찾아 숫자를 하나 더 올려줍니다. (예: `versionCode = 5` 였다면 `versionCode = 6`으로)
> 3. 앱 사용자들에게 보여질 표면적인 버전 이름인 `versionName`도 상황에 맞게 갱신해 줍니다. (예: `"1.6.2"` -> `"1.7.6"`)
>
> **마무리 공통 작업**
> 위 오류들을 수정한 뒤 `Step 1`의 터미널 명령어(`flutter build appbundle --release`)를 다시 실행하여 따끈따끈한 새 AAB를 구워 올리시면 무사 통과할 수 있습니다!
